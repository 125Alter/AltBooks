# AltBooks — книжный магазин на React

Итоговая практическая работа по React. Тема № 4 «Книжный магазин»: сущность CRUD — **книга**, внешний API — **Open Library Search**.

## Возможности
- Публичный каталог: поиск по названию/автору, фильтр по жанру, **фильтр по цене (от/до)**, «только в наличии», сортировка.
- Страница книги `/books/:id`.
- Регистрация с выбором роли (покупатель или автор), вход, выход, восстановление сессии после перезагрузки. Пароль — минимум 8 символов, с заглавной и строчной буквой, цифрой и спецсимволом; проверяется и на клиенте, и на сервере.
- Корзина: кнопка «В корзину» на карточке и странице книги, «Купить сразу», изменение количества, корзина сохраняется между визитами (у каждого пользователя своя).
- Оформление заказа: кнопка «Заказать» открывает форму с данными карты и адресом доставки; при ошибках в полях заказ не оформляется. Реквизиты карты остаются в браузере и на сервер не отправляются (оплата имитируется). Остатки списываются на сервере, заказ проходит целиком или не проходит вовсе.
- Отзывы: оценка 1–5 и текст на странице книги, средняя оценка на карточках. Один отзыв на книгу от пользователя; на свою книгу отзыв оставить нельзя.
- Вся карточка книги кликабельна и ведёт на страницу книги.
- Тёмная тема: переключатель 🌙/☀️ в шапке, выбор запоминается в браузере (или берётся из системной темы при первом визите).
- Предупреждения: модератор/админ может сначала выдать пользователю предупреждение с текстом (жёлтая плашка у него на всех страницах), а позже снять его или заблокировать. Блокировка заменяет предупреждение.
- Профиль `/profile`: смена имени (без пароля), смена пароля (по текущему; остальные устройства разлогиниваются), смена почты (по паролю; почта скрыта маской, пока не нажата «Сменить почту») и удаление аккаунта (по паролю; единственного админа удалить нельзя).
- Адаптивная навигация: на экранах уже 760px меню сворачивается в гамбургер.
- Страница «Мои заказы» с составом, суммой и адресом.
- Кабинет автора: создание, редактирование и удаление (с подтверждением) своих книг.
- Страница `/explore`: живой GET-запрос к Open Library, состояния loading / error / empty, кнопка «Повторить», отмена запроса через `AbortController`, сортировка и фильтр «только с обложкой», импорт найденной книги в свой каталог.
- Роли и права:

| Действие | Гость | Покупатель | Автор | Модератор | Админ |
|---|---|---|---|---|---|
| Смотреть каталог и книги | да | да | да | да | да |
| Покупать | нет (вход) | да | да | да | да |
| Оставлять отзывы (кроме своих книг) | нет | да | да | да | да |
| Удалять свои отзывы | — | да | да | да | да |
| Удалять чужие отзывы | нет | нет | нет | да | да |
| Добавлять книги | нет | нет | да | нет | да |
| Править книги | нет | нет | только свои | нет | любые |
| Удалять книги | нет | нет | только свои | любые | любые |
| Страница `/moderation` | нет | нет | нет | да | да |
| Предупреждать, блокировать и удалять аккаунты | нет | нет | нет | покупателей и авторов | любые, кроме своего |
| Страница `/admin`, пользователи и роли | нет | нет | нет | нет | да |

Блокировка: заблокированный пользователь входит, но на любой странице, кроме входа, регистрации и профиля, его перекидывает на страницу блокировки (`/blocked`) с причиной. Покупки, отзывы и свои книги ему недоступны (сервер отвечает 403), но в профиле он может сменить имя и почту или удалить аккаунт — на случай, если блокировка связана с ними. Удаление аккаунта убирает также его книги (с отзывами на них), отзывы и заказы.

Роль модератора назначает администратор на странице `/admin/users`; при регистрации её выбрать нельзя. Первый администратор создаётся при первом запуске; через регистрацию им стать нельзя. Дальше администратор сам назначает роли на странице `/admin/users` (в том числе делает других администраторами). Свою роль менять нельзя — так в системе всегда остаётся хотя бы один админ. Права проверяются на сервере.

## Стек
React 18, React Router DOM 6, Vite, Express 4, bcryptjs, cookie-parser. Данные хранятся в JSON-файле `server/data/db.json`.

## Запуск
Нужен Node.js 20+.
```bash
npm install
npm run dev
```
Сайт: http://localhost:5173, API: http://localhost:3001 (Vite проксирует `/api`).

Продакшен-режим: `npm run build`, затем `npm start` — Express отдаст и API, и собранный сайт на http://localhost:3001.

### Администратор
При первом запуске создаётся админ и 8 демо-книг.
Email: `admin@bookshop.local`, пароль по умолчанию — `Admin12345!`.
Свои данные: `ADMIN_EMAIL=... ADMIN_PASSWORD=... npm run server` (только до первого запуска; чтобы пересоздать данные, удалите `server/data/db.json`).

Если база `server/data/db.json` уже создана со старым паролем `admin12345`, новый пароль по умолчанию на неё не подействует — это значение используется только при самом первом запуске. Проще всего удалить файл и запустить сервер заново (тогда пересоздадутся и демо-книги), либо войти под старым паролем и ничего не менять: новая политика пароля действует только при регистрации через форму.

| `/books/:id` | все | карточка книги |
| `/explore` | все | Open Library |
| `/register`, `/login` | все | регистрация, вход |
| `/profile` | вошедшие (и заблокированные) | имя, почта, удаление аккаунта |
| `/blocked` | заблокированные | сообщение о блокировке и причина |
| `/cart` | вошедшие | корзина и оформление заказа |
| `/orders` | вошедшие | мои заказы |
| `/dashboard` | автор, admin | мои книги |
| `/books/new`, `/books/:id/edit` | автор, admin | создание и правка |

## API backend
| Метод и путь | Доступ |
|---|---|
| `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me` | — |
| `GET /api/books`, `GET /api/books/:id` | публично |
| `GET /api/books/mine`, `POST /api/books` | автор или admin |
| `PUT /api/books/:id` | admin — любые; автор — свои; иначе 403 |
| `DELETE /api/books/:id` | admin и модератор — любые; автор — свои; иначе 403 (отзывы книги удаляются вместе с ней) |
| `GET /api/books/:id/reviews` | публично |
| `POST /api/books/:id/reviews` | вошедший (не владелец книги; один отзыв на книгу) |
| `DELETE /api/reviews/:id` | автор отзыва, модератор или admin |
| `GET /api/reviews` | moderator, admin |
| `GET /api/moderation/users`, `POST /api/moderation/users/:id/block` (причина обязательна), `POST …/warn`, `POST …/unwarn`, `POST …/unblock`, `DELETE /api/moderation/users/:id` | moderator (только user и author), admin (любые, кроме себя) |
| `POST /api/orders` (позиции + адрес), `GET /api/orders/mine` | вошедший (не заблокированный) |
| `PATCH /api/auth/profile` (имя), `PATCH /api/auth/password` (текущий + новый), `PATCH /api/auth/email` (почта + пароль), `DELETE /api/auth/account` (пароль) | любой вошедший, в том числе заблокированный |
| `GET /api/admin/stats`, `GET /api/admin/users`, `PATCH /api/admin/users/:id/role` | admin |

Сессия — случайный токен в HttpOnly-cookie; пароли хранятся как bcrypt-хеш; права проверяются на сервере.

## Внешний API
`GET https://openlibrary.org/search.json?q=...&limit=24&fields=key,title,author_name,first_publish_year,cover_i,subject`
Нужны только поля, которые показываются пользователю: название, авторы, год, обложка, темы. Поиск отправляется по кнопке, чтобы не превышать лимиты Open Library. В ответе нет цен, поэтому фильтр по цене работает в каталоге магазина.

## Проверка по сценариям преподавателя
1. Создать книгу, обновить страницу — данные на месте.
2. Зарегистрировать второго автора и выполнить `PUT/DELETE` чужой книги — ответ 403; покупатель на `POST /api/books` тоже получает 403.
3. Войти и обновить страницу — сессия восстанавливается.
4. Выйти и открыть `/dashboard` — редирект на `/login`, после входа возврат на `/dashboard`.
5. Отправить форму с пустыми полями — сообщения об ошибках.
6. Отключить интернет на `/explore` — ошибка и кнопка «Повторить».
7. Открыть `/books/несуществующий-id` и `/abc` — сообщение «Такой книги нет» и 404.
8. Изменить поиск и сортировку на `/explore` — список обновляется без перезагрузки.

Валюта меняется в одной константе: `src/utils/format.js` (`CURRENCY`).
